## 1. "불편" 의 기준

기준 예시(기획자): **지퍼를 잘못 잠금 · 단추를 잘못 잠금 · 청소기가 안 들어가서 청소가 안 됨**
→ 일상에서 누구나 겪어 봤고, 사소한데 **굉장히 꼴받는** 순간.

새 아이디어는 아래 6개를 모두 만족해야 채택한다.

| # | 기준 | 탈락 예 |
|---|---|---|
| 1 | **공감**: 설명 없이 그림만 봐도 "아 이거 진짜 짜증나" | 특정 직업·지역만 아는 상황 |
| 2 | **원인이 사소함**: 한 칸 밀림, 한 끗 차이, 방향 틀림, 끝을 못 찾음 | 사고·재난·다툼 같은 큰 문제 |
| 3 | **동사 하나**: 지시문이 `~해줘!` 한 마디 (스케치 톤: "껍질을 없애줘!", "USB를 꽂아줘!") | 규칙 설명이 필요한 것 |
| 4 | **한 손가락 조작**: 탭 / 연타 / 홀드 / 드래그 / 긋기 / 문지르기 / 돌리기 중 하나 (D-10) | 멀티터치, 키보드 |
| 5 | **5초 안에 해결** (회피 페이즈용은 3초) | 길게 탐색해야 하는 것 |
| 6 | **실패가 웃김**: 그 짜증을 과장한 실패 연출이 그려짐 (김 찢어짐, 천 씹힘, 과자 폭발) | 그냥 "실패" 글자만 뜨는 것 |

## 2. 분류 체계

### 불편 유형 (카테고리)
미니게임 풀·스쿼드 캐릭터·몬스터 테마를 나누는 기준이다 (ROADMAP D-11, D-14).

| 코드 | 유형 | 예 |
|---|---|---|
| `Food` | 먹을 때 | 삼각김밥, 컵라면 뚜껑, 과자봉지, 케첩 |
| `Wear` | 입을 때 | 지퍼, 단추, 후드끈, 옷 택 |
| `Device` | 기계·전자기기 | USB, 보호필름 기포, 꼬인 충전기 줄, 리모컨 건전지 |
| `Home` | 집안일 | 청소기, 휴지 끝, 액자 수평, 멀티탭 |
| `Outside` | 밖에서 | 교통카드 두 장, 자동문, 엘리베이터, 주차 티켓 |
| `Peel` | 뜯기·떼기 | 스티커, 테이프 끝, 요거트 뚜껑 |

### 조작 유형
현재 구현된 입력: `TapInteraction`, `DragInteraction`, `HoldInteraction` (`Assets/Scripts/Input/Interaction/`).
★ 표시는 **새로 필요한 입력** → ROADMAP F-32.

| 조작 | 설명 | 상태 |
|---|---|---|
| 탭 | 대상 누르기 | 있음 |
| 연타 ★ | 짧은 시간에 여러 번 탭 (횟수·속도) | Tap 확장 |
| 홀드 | 누르고 있기 / 알맞은 때 떼기 (게이지) | 있음 |
| 드래그 | 대상을 잡아 옮기기 (속도 제한 가능) | 있음 |
| 긋기 ★ | 경로(선)를 따라 한 번에 긋기, 경로 이탈 정도 판정 | 신규 |
| 문지르기 ★ | 좌우/상하 왕복 스와이프 (횟수) | 신규 |
| 돌리기 ★ | 대상 주위로 원 그리기 → 회전각 | 신규 |

### 용도
| 용도 | 쓰임 | 조건 |
|---|---|---|
| `Energy` | 에너지 수집 페이즈 (연속 출제) | 3~5초 |
| `Evasion` | 회피 페이즈 (적 공격마다 1개) | **3초 이하**, 지시문 보자마자 반응 가능 |
| `Special` | 몬스터 특수 공격 (회피 페이즈의 어려운 버전) | 해당 몬스터 테마 유형 |

## 7. VacuumWidenMiniGame 명세 (MG-45 '청소기를 맞춰줘!')

Home · 집안일 유형. 흡입구 폭을 가구 틈에 맞게 늘린 뒤 위로 밀어 넣어 먼지를 빨아들이면 성공. 이 명세만으로 스크립트·씬을 만들 수 있도록 필드·수치·판정을 모두 적는다. `VacuumMiniGame.cs` 구조(MiniGameBase, PointerInput, Mode 열거, 실패 우선 판정, 흔들기 연출)를 그대로 따른다.

### 7.1 오브젝트 목록

| 오브젝트 | 역할 |
|---|---|
| Manager (VacuumWidenMiniGame 컴포넌트) | 전체 로직 |

### 7.2 public 필드 (VacuumWidenMiniGame : MiniGameBase)

- `Transform head, headSprite, widthHandle, leftFurniture, rightFurniture, startPos, gapPos`
- `BoxCollider2D headCollider, gapZone`

### 7.3 난이도별 수치 (`OnBegin(ctx)` 의 `ctx.Difficulty`, 1~3 — `VacuumMiniGame.cs` 실제 패턴과 동일, `static int Level` 아님)

| Level(`ctx.Difficulty`) | 허용 오차 tolerance | 틈 폭 범위 (gapMin~gapMax) | 안내 화살표 |
|---|---|---|---|
| 1 | 0.5 (월드) | 1.6 ~ 2.4 | 표시 |
| 2 | 0.35 | 1.4 ~ 2.0 | 표시 |
| 3 | 0.2 | 1.2 ~ 1.6 | 숨김 |

공통 수치: `minWidth`(= `startWidth`) 1.2, `maxWidth` 4.0, `headHeight` 0.6(그림), Head 콜라이더 높이 1.2, WidthHandle 반지름 0.6, `handleGap` 0.75(핸들 중심 = `width/2 + handleGap`).

수치는 T6.1에서 코드/씬 실제값에 맞춤; 밸런스 확정은 TEST_SCENARIO §2-R 플레이 후.

### 7.4 조작

- WidthHandle 드래그(폭): `width = clamp(widthAtGrab + 2 * (pointer.x - grabX), minWidth, maxWidth)`, 좌우 대칭으로 늘어남. **틈 밖(IsInsideGap == false)일 때만 변경 가능** — 틈 안에서 폭을 바꾸는 것은 막는다.
- Head 드래그(밀기): `head.position.y = clamp(pointer.y, startPos.y, gapPos.y)`, x는 고정.
- 손을 떼면 `Mode.None`으로 복귀.
- 대상 판정: `Camera.main.ScreenToWorldPoint(Input.mousePosition)` → `Physics2D.Raycast(pos, Vector2.zero)`로 WidthHandle(Mode.Width) 또는 Head(Mode.Push) 중 맞은 쪽을 잡음.

### 7.5 판정 순서 (매 프레임, 실패를 먼저 확인)

`headTop = head.position + (0, headHeight/2)`

1. `IsInsideGap (= GapZone.OverlapPoint(headTop))` 이고 `width > gapWidth + tolerance` → **Failed(넓음·쾅)**
2. `Dust.OverlapPoint(headTop)` 이고 `width < gapWidth - tolerance` → **Failed(좁음·먼지 남음)**
3. `Dust.OverlapPoint(headTop)` → **Success**

시작 시 `gapWidth = Random.Range(gapMin, gapMax)` (`ctx.Difficulty`에 맞는 배열 값). 제한 시간은 MiniGameBase/러너 기본값을 따르고 따로 두지 않는다.

### 7.6 연출

- `OnBegin(ctx)`: `int difficulty = Mathf.Clamp(ctx.Difficulty, 1, 3)`, `gapWidth` 추첨, 가구·GapZone을 `gapWidth`에 맞게 배치, Head를 StartPos로, `width = startWidth`, `arrow.SetActive(difficulty < 3)`.
- `OnResolved`:
  - 성공 → `isSuccess` true, Dust scale 0 (사라짐).
  - 넓음 실패(쾅) → `isFailed` true, Head/HeadSprite 색을 `failedColor`로, 가구를 0.3초간 흔듦(ShakeFurniture, Vacuum의 ShakeSofa 패턴).
  - 좁음 실패(먼지 남음) → `isFailed` true, Dust scale 0.5로 남겨둠.
  - 결과가 나오면 입력을 멈춘다(`IsRunning` false).

### 7.7 히트 영역 최소 px 기준 (UI_DESIGN §28 참조, 108px/unit)

- Head 콜라이더: `BoxCollider2D size = (max(width, 1.2), 1.2)` → 높이 1.2 × 108 = 129.6px ≥ 120px 기준 충족.
- WidthHandle: `CircleCollider2D radius = 0.6` → 지름 1.2 × 108 = 129.6px ≥ 120px 기준 충족.
- GapZone·Dust는 입력 대상이 아니므로(판정 전용 트리거) 기준 적용 대상이 아님. 레이어를 Ignore Raycast로 두어 PointerInput의 Head/WidthHandle 피킹을 막지 않도록 한다 — **T3·T4에서 PointerInput.RaycastWorld2D의 레이어 마스크가 Ignore Raycast를 실제로 거르는지 확인 필요** (미확인 상태로 인계).
